How to use VoiceBox STS Sidecar

Convert an authorized speech recording or video into the voice of a selected local VoiceBox profile. This guide explains every control on the application page, the available formats, and what the status messages mean.

Start here

VoiceBox STS Sidecar runs locally in your browser while the bridge service handles media processing on the same computer. Start VoiceBox first, then launch the bridge with the compiled app or start-bridge.bat. The homepage opens at http://127.0.0.1:8765.

Before you begin

  • VoiceBox must be running and reachable on its local loopback service.
  • FFmpeg and FFprobe must be installed and available to the bridge.
  • OpenVoice must be installed and its local model checkpoint available.
  • An NVIDIA CUDA device is recommended. CPU mode is supported but substantially slower.
  • Only use voices and media you own or are authorized to process.

1. Choose a target voice

  1. Wait for the VoiceBox health message to report that the local service is available.
  2. Open Cloned profile and choose the VoiceBox voice you want to use.
  3. Open Reference sample and choose the sample that best represents the target voice. If a profile has only one sample, it is selected automatically.
  4. Click Cache selected reference WAV. The bridge downloads the reference through VoiceBox's local API and stores a project-local copy for conversion.
Tip: Choose a reference with clear speech and a similar speaking style to the intended result. The reference establishes speaker identity; the source recording supplies timing, emphasis, and delivery.

2. Check the conversion engine

This card reports the isolated OpenVoice runtime, checkpoint, configured device, and native audio format.

Control or indicatorWhat it means
RuntimeThe Python environment used for local OpenVoice inference.
CheckpointThe locally verified converter model and its readiness state.
DeviceThe configured inference target, such as cuda:0 or cpu.
Load model and probeLoads the model and runs a small local readiness check. Do this before a first conversion or after changing the runtime.

The engine operates at 22.05 kHz mono. The bridge preserves the source timeline, but the model's native output is mono.

3 and 5. Convert local audio

  1. Click Choose source audio and select an authorized file.
  2. Wait for the upload status to confirm that the complete file was stored.
  3. Choose the target voice, adjust pitch or tone if needed, and click Convert with selected profile.
  4. When the job completes, use Audition latest output or the output player to listen to the validated WAV.

The audio upload limit is 1 GiB. The original filename is retained as metadata, while the stored file uses a UUID-based name inside the project data directory.

Settings are saved separately for each selected VoiceBox profile. Use Reset to profile defaults to return that profile's saved starting values. Adjustments are applied once to the completed converted track and the bridge verifies the original frame count afterward.

6. Convert a YouTube video

This workflow is for a direct, authorized HTTPS YouTube video URL. The bridge downloads one source locally, converts the full soundtrack in aligned chunks, and creates a new video using the original video stream.

  1. Select a target profile and reference sample.
  2. Paste a direct YouTube URL. Watch, Shorts, Live, Embed, and youtu.be links are supported when they identify one video.
  3. Select MKV or MP4 under Video output format.
  4. Set pitch and tone adjustments if desired.
  5. Check the permission confirmation, then click Download and convert video.
  6. Leave the bridge running while the stages progress. A refresh reconnects to the latest job.

Single-video cache

The cache keeps one validated active YouTube source keyed by canonical video ID. Reusing the same video avoids another yt-dlp request. Save original YouTube source downloads the active original beside the cache controls, so save it before using Clear cache or replacing the cached video. Clearing the cache removes the cached source only; completed outputs remain available.

Accepted URL scope: The app rejects arbitrary hosts, HTTP URLs, credentials, custom ports, playlists without a direct video, search pages, and restricted access that requires account cookies. It does not bypass DRM or access controls.

7. Convert a video from this PC

  1. Click Choose video from this PC and select an authorized local video.
  2. Wait for the upload to finish. The local-video player lets you preview the imported source when your browser supports its codec.
  3. Select MKV or MP4 under Video output format.
  4. Confirm that you own the video or have permission to convert it.
  5. Click Convert imported video and follow the progress monitor.

Imported video is stored under a UUID address in the project data directory. The browser never sends an arbitrary filesystem path to the conversion API. The upload safety limit is 12 GiB, and the source must contain both a video stream and an audio stream. When the job completes, Save original imported video appears beside the finished output. This source link and the preview are restored after a page refresh while the managed source remains available.

Players, downloads, and completed jobs

  • Audio player: audition the uploaded source, selected reference, or latest converted WAV.
  • Local video player: preview the imported source before conversion and download the original imported file.
  • Finished video: play the completed output when the browser supports its container and copied video codec.
  • Save original: use Save original YouTube source for the active YouTube cache or Save original imported video beside a completed local-video job.
  • Open or save the output: downloads with the correct .mkv or .mp4 extension.
  • Details panels: show the selected profile, job ID, stage information, probes, validation, and any error message.
Validation guarantee: A video result is not published as completed until FFprobe checks its streams and FFmpeg fully decodes it. The bridge also checks the copied video codec, requested audio codec, and timeline.

Files, storage, and automatic cleanup

Runtime files stay inside the configured project data directory and are not committed to the repository. The main locations are:

  • inputs/ Ã¢â‚¬â€ uploaded audio files and metadata.
  • video_inputs/ Ã¢â‚¬â€ imported local video files and metadata.
  • references/ Ã¢â‚¬â€ cached VoiceBox reference WAV files.
  • outputs/ Ã¢â‚¬â€ converted WAV files.
  • video_jobs/ Ã¢â‚¬â€ durable video manifests and final video outputs.
  • youtube_cache/ Ã¢â‚¬â€ the single active validated YouTube source.

At bridge startup, manifest-driven garbage collection marks abandoned queued/running video jobs as interrupted, removes old failed jobs, prunes large intermediate audio/chunk/download data from retained completed jobs, removes completed jobs past retention, and removes unreferenced imported videos after their grace period. Invalid manifests are preserved for inspection.

Defaults are 30 days for completed video jobs, 24 hours for failed jobs, and 24 hours for unreferenced local-video uploads. These can be changed with BRIDGE_VIDEO_JOB_RETENTION_DAYS, BRIDGE_FAILED_VIDEO_JOB_RETENTION_HOURS, and BRIDGE_ORPHAN_VIDEO_INPUT_RETENTION_HOURS.

Privacy, ownership, and permissions

Keep the bridge on loopback. The intended address is 127.0.0.1; do not expose the unauthenticated API to a network unless you have deliberately secured it.

Use authorized material. Process only voices, recordings, videos, and YouTube sources that you own or have permission to use. The confirmation checkboxes are an explicit part of the video workflows.

Local processing. Inference, cached references, uploaded files, downloaded sources, and generated outputs remain on the local computer. YouTube jobs necessarily contact YouTube only when acquiring a cache miss.

Troubleshooting

VoiceBox is unavailable

Start VoiceBox, confirm its local API is healthy, and reload the page. The profile list cannot populate until the service responds.

The engine is not ready

Run the engine probe and read the engine details. Confirm the isolated environment, checkpoint, and configured CUDA/CPU device.

A file will not import

Check its extension, size limit, and that the contents are decodable. A video must contain both video and audio streams.

The browser cannot play a video

Browser codec support is narrower than FFmpeg support. Use the download link and open the validated file in VLC or another capable local player.

YouTube downloads again

Check that the URL identifies the same canonical video ID and that the cache panel shows an active validated source.

A long job stops

Keep the bridge process running. A page refresh is recoverable; terminating the bridge ends the active GPU task, although manifests remain for diagnosis.
